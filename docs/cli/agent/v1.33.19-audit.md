# v1.33.19 audit — tool call failures + memory bugs

Date: 2026-05-14
Status: audit only, no fixes applied
Scope: why does the CLI lose context, hang, or fail tool calls?
Method: three parallel evidence-based audits across `src/kernel/agent-loop.ts`, `src/context/*`, `src/state/db.ts`, `src/tui/ink/*`, `src/cli/interactive.ts`, `src/providers/*`.

All findings cite file:line. Severity ladder: **P0 blocking** (data loss / hard hang) → **P1 degraded** (wasted turn / silent corruption) → **P2 cosmetic** (UX only).

Subsequent fixes for findings in this report will be dispatched through DeepSeek v4-pro per project policy. Each fix needs a regression test before landing.

---

## Headline

The 400-error recovery ladder, tool pairing sentinel injection, and stream stall timeout are **working** in v1.33.19. The CLI does NOT crash on bad message sequences anymore.

Three classes of bug remain:

1. **Ink TUI is missing pieces that readline has** — no session persistence, no loop detector. Crash mid-turn = data loss on Ink only.
2. **Compaction can collapse the entire preserved window** when its output interacts with the orphan stripper. User sees "context was lost".
3. **Silent error swallowing** in summarizer, KB query, soul/primer, and JSON-arg repair leaves the agent quietly weaker without surfacing the failure.

## P0 — data loss / hard hang

### P0-1. Ink TUI does not pass `session` or `loopDetector` to `runAgentLoop`

| | |
|---|---|
| File | `src/tui/ink/App.tsx:1001-1016` |
| Compare | `src/cli/interactive.ts:384-399` (readline path) |
| Symptom | Crash mid-turn on Ink loses the final turn. No loop detection fires when a tool refuses with identical args repeatedly. |
| Status | **Latent in v1.33.19** |

Readline call passes `loopDetector` and `session`:

```ts
// interactive.ts:384
const result = await runAgentLoop({
  sessionId, model, messages: turnHistory, tools, maxTurns, provider,
  toolExecutor, approvalBus, autoApprove, events, signal,
  errorClassifier, loopDetector, session,  // ← BOTH present
  ...
});
```

Ink call omits both:

```ts
// App.tsx:1001
const result = await runAgentLoop({
  sessionId: sessionIdRef.current, model, messages, tools, maxTurns, provider,
  toolExecutor, approvalBus, events, signal,
  contextTransform, errorClassifier, autoApprove,
  // session: ← MISSING
  // loopDetector: ← MISSING
  ...
});
```

The downstream effect:

- `runAgentLoop` calls `void cfg.session?.append(...)` per turn for crash-safe checkpointing. With no session, **nothing is checkpointed mid-turn**. The Ink-side fallback `void sessionRef.current?.append(...)` at App.tsx:1018-1024 runs only AFTER `runAgentLoop` returns. Crash during the loop = lost turn.
- No loop detector means tools that keep refusing with identical inputs are not detected at the kernel level; only the REFUSAL_ABORT_THRESHOLD inside the loop catches it.

### P0-2. Compaction → orphan strip can erase entire conversation

| | |
|---|---|
| File | `src/kernel/agent-loop.ts:464-491`, `_stripOrphanedToolResults` at line 300 |
| Symptom | "Hello! It seems our previous conversation context was lost..." |
| Status | **Latent in v1.33.19** |

Sequence that triggers it:

1. History: `[system, user("task"), assistant(tool_use_A, text), user(tool_result_A), user("task2"), ...]`
2. `contextTransform` compacts the early window into a synthetic `[Compacted summary of earlier turns]` user + `Got it.` assistant pair (compaction.ts:145-176).
3. Preserved window now starts with a `tool_result` that has no preceding `tool_use` above it.
4. `_stripOrphanedToolResults` at line 300 removes that message (correct).
5. If the preserved window had only that orphan, `messagesForCall.length === 0` (line 466).
6. `_recoverMinimalContext` (line 332) is called. It returns only system messages + last text-containing user message. **Everything between is gone.**

The user-visible fallback message at line 349-355 instructs the model to "resume silently" but this is a directive, not a guarantee — weaker models still ask "could you restate?".

The orphan check at line 300-325 only matches messages where **every** part is a `tool_result`:

```ts
if (msg.role === "user" && Array.isArray(msg.content)
    && msg.content.every((p) => p.type === "tool_result")) { ... }
```

Mixed messages (text + tool_result in one user turn) are NOT stripped — they survive and trigger 400s on the next turn, kicking the repair ladder into action.

## P1 — degraded / wasted turn

### P1-1. Fire-and-forget session append on Ink TUI

| | |
|---|---|
| File | `src/tui/ink/App.tsx:1018-1024` |
| Compare | `src/cli/interactive.ts:424-428` (await each append) |
| Symptom | Ink crash mid-turn truncates session JSONL; replay loses final assistant message. Readline path unaffected. |
| Status | **Latent in v1.33.19** |

```ts
// App.tsx (current)
for (const msg of result.messages.slice(prevHistoryLen)) {
  void sessionRef.current?.append({ type: "message", ts, message: msg });
}
```

vs.

```ts
// interactive.ts (current)
for (const msg of result.messages.slice(initialCount)) {
  await session.append({ type: "message", ts, message: msg });
}
```

Node does not flush pending `fs.appendFile` on `process.exit`. Ink's React render cycle exit happens before the writes drain.

### P1-2. Compaction summarizer errors are silent + lossy fallback

| | |
|---|---|
| File | `src/context/compaction.ts:245-311` (two-pass summarize), 145-176 (truncate fallback) |
| Symptom | Long-running tool outputs silently corrupted; model later asks "what was that result again?" |
| Status | **Latent in v1.33.19** |

Both summarization passes catch every error and return `""`. When both fail, `finalSummary === ""` and the code falls back to `truncateLargeToolOutputs`, which truncates tool outputs over 2000 chars to `[head]...[tail]` — silently discarding the middle 80%.

No event is emitted. The compaction smoke test at `scripts/qa-app/compaction_test.mjs` only exercises happy-path + veto. Summarizer-error path is not covered.

### P1-3. Stream timeout can leave incomplete tool_use in history

| | |
|---|---|
| File | `src/kernel/agent-loop.ts:504-542` |
| Symptom | Provider stalls during streaming → assembled turn contains tool_use with `input: {}`; next turn wastes a round-trip. |
| Status | **Latent — partially mitigated by 400-ladder** |

When stream times out mid-tool-arg, `assembleTurn` (line 715) processes whatever events arrived. `safeParse` (message.ts:161) returns `{}` on broken JSON. The tool_use lands in history with empty input. The 400 ladder eventually catches the malformed call but at the cost of an extra round-trip.

### P1-4. Mid-history orphaned tool_result not stripped

| | |
|---|---|
| File | `src/kernel/agent-loop.ts:300-325` |
| Symptom | User sees "Tool history stripped due to repeated API errors" on turn N+1 after compaction. |
| Status | **Active — by design but visible regression vector** |

The strip predicate is `every part is tool_result`. A user message like `[{type:"text"}, {type:"tool_result"}]` survives. After compaction, surviving orphans hit the provider as malformed → 400 → repair ladder runs.

### P1-5. Provider-wide cooldown is too coarse

| | |
|---|---|
| File | `src/intelligence/health-monitor.ts:46-61` |
| Symptom | One hanging model (e.g., `minimax-m2.7`) poisons the entire provider's cooldown; other models on that provider get collaterally throttled. |
| Status | **Latent in v1.33.19 — design regression from v1.20.34** |

Memory note `feedback_free_models_routing.md` references per-model auto-demotion in v1.20.34. v1.33.19 has only provider-wide cooldown. A single bad model can mute all of NIM or all of OpenRouter for the cooldown window.

### P1-6. DB vec extension race on first KB query

| | |
|---|---|
| File | `src/state/db.ts:63-84` |
| Symptom | First `/kb-query` (or any RAG injection) within ~200ms of CLI startup silently times out; later queries work. |
| Status | **Latent in v1.33.19** |

```ts
setImmediate(() => {
  loadVecExtension(db);
  bootstrapIndexOnce(db);
  _deferredDone = true;
});
```

`kb-query.ts:25-54` wraps the query in `Promise.race([query(), timeout])` and returns `undefined` on either branch. No log, no event. KB context silently absent on the first turn after launch.

### P1-7. _hardenHistory Pass 2 can erase end-of-history tool calls

| | |
|---|---|
| File | `src/kernel/agent-loop.ts:163-227` |
| Symptom | If the model's last assistant turn ended with a tool_use and the next user turn never arrived, the synthetic-user injection + Pass 4 strip can erase the whole tail. |
| Status | **Latent — narrow edge case** |

Pass 2 injects `syntheticUser` with only `sentinelParts` (tool_results). Pass 4's `_stripOrphanedToolResults` then matches the predicate and drops it, taking the model's prior tool call out of memory. Rare but real if a tool times out and the loop exits with no response.

### P1-8. Tool timeout does not SIGKILL child processes

| | |
|---|---|
| File | `src/tools/exec.ts:102-110`, `src/kernel/agent-loop.ts:978-995` |
| Symptom | Long-running shell/MCP children keep executing in the background after the 120s timeout; can interfere with the retry. |
| Status | **Latent — documented in v1.33.3 audit** |

The timeout aborts the AbortController and returns `{content: "[TIMEOUT]...", isError: true}` but does not `process.kill(pid, 'SIGKILL')` on the spawned child. Tools that ignore the abort signal keep running.

## Round 2 — paste UX, loop detector, agent-call infrastructure

### Paste UX

#### P1-9. History up-arrow re-fires `detectPaste` on recalled prompts

| | |
|---|---|
| File | `src/tui/ink/components/InputBox.tsx:242, 286-296` |
| Symptom | User recalls a previous prompt that contained a paste; the recalled text triggers a fresh paste-collapse on entry. Expected behaviour is plain text recall. |
| Status | **Regression introduced/exposed by v1.33.19 collapse fix** |

`handleChange` always runs `detectPaste(prevValueRef.current, sanitized)` regardless of source. Up-arrow recall calls `props.onChange(history[N])` which feeds the recalled text through the same path. The char-delta heuristic fires and the recalled prompt collapses. Guard needed: skip detection when the change is sourced from history navigation.

#### P1-10. detectPaste runs synchronously, pasteSegment state is async

| | |
|---|---|
| File | `src/tui/ink/components/InputBox.tsx:101-104, 242-247` |
| Symptom | A keystroke landing in the same React tick as the paste sees `pasteSegment === null`; the collapsed-mode branch in `useInput` (line 313) doesn't run. The follow-up key reaches TextInput as normal text instead of nuking the paste. |
| Status | **Narrow race — observable with scripted input / autofill** |

`setPasteSegment(seg)` queues a re-render; the actual state change lands next tick. If keystrokes are batched fast enough (script-fed, autofill, debouncer flush), the gap is exploitable. Real human typing rarely hits this.

#### P1-11. Stale pasteSegment can outlive value reset

| | |
|---|---|
| File | `src/tui/ink/components/InputBox.tsx:175-184, 319-329` |
| Symptom | Parent clears the buffer via `props.onChange("")` without clearing pasteSegment. Backspace then computes `slice(0, start) + slice(end)` on the empty string → no-op, but the collapsed view stays rendered. |
| Status | **Latent** |

Add `pasteSegment.end <= value.length` precondition before any slice. Same guard belongs on the print-char branch (line 332).

#### P2-7. Expanded paste is read-only

| | |
|---|---|
| File | `src/tui/ink/components/PasteCollapse.tsx:88-96`, `src/tui/ink/components/InputBox.tsx:453-470` |
| Symptom | `Ctrl+E` expands the paste into a `<Text>` block, not into TextInput. User cannot edit the pasted content in-place. Any printable key falls through to the print-char branch which clears collapse + appends — not "edit inside the paste". |
| Status | **UX gap; behaviour is consistent with the placeholder hint but underspecified** |

Either rename the affordance ("preview" rather than "expand") or actually mount TextInput when expanded.

#### P2-8. 199-char / 3-line paste falls below both thresholds

| | |
|---|---|
| File | `src/tui/ink/components/PasteCollapse.tsx:16-17, 31-35` |
| Symptom | Three 66-char lines (total 199 chars) trigger neither `PASTE_CHAR_THRESHOLD` (200) nor `PASTE_LINE_THRESHOLD` (4). Realistic for short code snippets. Renders inline. |
| Status | **Cosmetic — boundary tuning** |

#### P2-9. textInputKey remount loses cursor position on every history nav

| | |
|---|---|
| File | `src/tui/ink/components/InputBox.tsx:113, 286-304` |
| Symptom | Up-arrow → `setTextInputKey(k => k + 1)` → TextInput unmounts and remounts → cursor defaults to buffer end. User expects cursor to land where it was in the recalled prompt. |
| Status | **By design, but user-visible** |

### Loop detector

#### P0-3. Ink TUI omits `loopDetector` (consolidated with P0-1)

| | |
|---|---|
| File | `src/tui/ink/App.tsx:1001-1016` vs `src/cli/interactive.ts:397` |
| Status | **Latent — already noted in P0-1**; re-listed here because the loop-detector blast radius is wider than session persistence |

Confirmed: Ink users never get pattern-1 (repeated identical tool call ≥5×) or pattern-2 (output stagnation ≥3 turns) loop detection. Only the kernel-internal `REFUSAL_ABORT_THRESHOLD=3` for *errored* tools fires — succeeding-but-looping tool calls are not caught at all on Ink.

#### P1-12. `LoopDetector.reset()` is never called

| | |
|---|---|
| File | `src/subagents/loop-detector.ts:79-83` |
| Symptom | `toolCallHistory: Map<string, number>` accumulates for the lifetime of the readline session. Long sessions grow the map unbounded (~100 bytes/entry × N tool calls). |
| Status | **Latent — moderate memory leak on multi-hour sessions** |

`reset()` is exported but `grep -rn 'loopDetector.reset\|\.reset()' src` returns zero call sites. Either call it between prompts in the readline loop or remove the dead API.

#### P1-13. JSON key-order false negatives in loop detection

| | |
|---|---|
| File | `src/subagents/loop-detector.ts:37` |
| Symptom | The detection key is `${name}:${JSON.stringify(args)}`. `{path, content}` and `{content, path}` serialize to different strings → counted as different calls. A misbehaving model can sidestep the threshold by reshuffling key order each call. |
| Status | **Latent — exploitable for jailbreak; rare in practice** |

Fix: stable-stringify (sort keys before JSON.stringify) before hashing.

| | |
|---|---|
| File | `src/kernel/__tests__/`, `scripts/qa-app/` |

### Architecture noted (not bugs)

- **Sub-agent dispatch is real.** `src/tools/task.ts` + `src/subagents/delegator.ts` spawn isolated `runAgentLoop` instances with scoped tool registries (`createScopedRegistry` at delegator.ts:143-173 returns a read-only view). The Ink TUI's `SubagentPanel` (`src/tui/ink/components/SubagentPanel.tsx:29-87`) tracks them via `toolcall_start` events with `name === "task"`.
- **Fleet runner is separate.** `src/fleet/runner.ts:242, 340, 359` emits `fleet_agent_*` events from a parallel orchestration layer distinct from the `task` tool path.
- **MCP shutdown is clean.** `StdioTransport.close()` at transport.ts:108-114 calls `child.kill()` and clears pending callbacks. `Promise.allSettled` in loader.ts:74 ensures all MCP closers run on SIGINT/SIGTERM.
- **Tool registry is closed after init.** No runtime plugin slot. MCP-bridged tools are the only post-init additions, gated by `lazyLoadMcp()`.
- **Slash commands do not dispatch sub-agents.** `/mcp`, `/fleet`, `/config`, `/provider`, `/memory`, `/update` are config/info only. Sub-agents are spawned exclusively through the model's `task` tool call.

## Recommended fix order (high → low ROI, all via DeepSeek v4-pro)

Each fix dispatched through DeepSeek must land with a focused regression test before merging. No batch fixes.

1. **P0-1 / P0-3**: Add `session` + `loopDetector` to Ink's `runAgentLoop` call. Two-line change. Regression test: kill Ink mid-turn, restart, verify session resumes with last turn intact; loop detector fires after 5 identical tool calls.
2. **P0-2**: Extend `_stripOrphanedToolResults` to detect mixed-content orphans (text + tool_result in same user message). Strip the tool_result parts in place rather than dropping the whole message. Add `compaction_test.mjs` case: history with mixed orphan must survive.
3. **P1-1**: Await session appends in Ink (or buffer + flush in cleanup). Regression test: forced exit mid-append, replay shows complete turn.
4. **P1-2**: Emit `compaction_failed` event when summarizer returns empty; surface in TUI status bar. Add test for summarizer-throws path.
5. **P1-5**: Move cooldown from provider-level to (provider, model) tuple. Restore per-model demotion semantics from v1.20.34.
6. **P1-6**: Replace `setImmediate` deferral in `db.ts` with a `_initPromise` that vector-ops paths await. Schema/migration stays fast.
7. **P1-9**: Guard `detectPaste` so history-recall does not trigger collapse. Add an `isHistoryRecall` flag through `props.onChange`, or skip detection when `prev === ""` and `next` matches a history entry.
8. **P1-12 / P1-13**: Call `loopDetector.reset()` between readline prompts; stable-stringify args before hashing.
9. **P1-15 / P1-16**: Wrap `beforeTurn` in try/catch (swallow + log like `afterTurn`); emit `tool_exec_start` on the `beforeToolCall` catch path.
10. **P2-1**: When `repairJSON` falls through to `{}`, return a synthetic `tool_result` with `isError: true` so the model can self-correct.
11. **P1-8**: After tool abort, send `process.kill(pid, 'SIGKILL')` to spawned children that didn't honor the abort within 2s.
12. **P2-11**: 60s wallclock timeout on `ApprovalBus.request`, resolving to `"deny"`.
13. **P2-12**: Bounded MCP server respawn (max 3/min) on stdio child exit.

Remaining P2 items are surface polish; bundle them into a UX sprint after the above ship.

### DeepSeek dispatch protocol

Each fix above is a separate DeepSeek call. Standard prompt shape:

1. Cite the audit finding ID (e.g. `P0-1`).
2. Paste the file:line, current code, and intended change.
3. Specify the regression test that must pass.
4. Forbid touching unrelated code in the same patch.
5. After DeepSeek returns the diff: `npm run typecheck && npm run test && npm run test:ink && tmux smoke` must all pass before staging.

The audit doc is the source of truth — fixes that drift from the documented scope get rejected.
